# Pacific Education — Stage 27 Controlled Pilot, User Testing & Evidence

## Status

**Stage 27 architecture contract: DEFINED — controlled pilot execution, evidence collection and review required.**

## 1. Pilot boundary

The current repository describes the initial controlled prototype pilot as **September 21, 2026 to October 21, 2026**, with an owner-approved extension only if a genuine need arises, up to a total of three months.

The pilot is for demonstration, testing, curriculum-alignment work and authorized feedback. It is not a production education service.

Do not enter real sensitive child information, passwords, payment credentials or exact child location information into the prototype.

## 2. Pilot participants

Participation must be authorized and limited to the approved pilot scope.

Participant roles should be documented, such as:

- Owner
- Pilot teacher
- Pilot learner/test account
- Parent/guardian tester where applicable
- Technical/support tester
- Curriculum reviewer

Real child participation should require the applicable safeguarding, authorization and consent processes.

## 3. Test scenarios

The pilot should test representative workflows including:

- Access and account flows
- Role and relationship boundaries
- Daily lessons
- Lesson completion/progress
- Assessments
- Assessment gates
- Teacher workflows
- Parent/guardian workflows
- Offline use
- Reconnection and synchronization
- Accessibility
- Low-bandwidth use
- Device compatibility
- Error handling
- Security and privacy controls
- Curriculum alignment workflows

## 4. Evidence collection

Each material test should record:

- Test ID
- Date/time
- Environment/device/browser
- Tester role
- Workflow
- Expected result
- Actual result
- Pass/fail
- Defect or observation
- Severity where applicable
- Evidence reference
- Reviewer/status

Avoid storing unnecessary personal information in test evidence.

## 5. Defect management

Pilot findings should be categorized and tracked.

Security, privacy, safeguarding, data-integrity and authorization defects must receive priority treatment.

A release-blocking defect must remain open until fixed, retested and documented as resolved or formally accepted through the applicable owner/review process.

## 6. Feedback

Feedback should distinguish:

- Bug reports
- Usability observations
- Accessibility barriers
- Curriculum-alignment findings
- Feature requests
- Training/support needs
- Operational issues

Feedback must not be treated as proof of production safety or legal compliance.

## 7. Pilot data protection

Prototype testing must continue to use test/demo data.

If production-like data is ever proposed for testing, the appropriate privacy, safeguarding, authorization and security review must occur first.

Pilot evidence must not expose passwords, payment credentials, unnecessary personal data or sensitive child information.

## 8. Pilot exit criteria

Before the pilot can support production-readiness decisions, evidence should demonstrate:

- Core workflows tested
- Role/relationship controls tested
- Lesson/progress behavior verified
- Assessment gates verified
- Offline/sync behavior verified
- Device and accessibility testing completed
- Curriculum mappings reviewed
- Security/privacy/safeguarding findings tracked
- Critical defects resolved
- User feedback reviewed
- Outstanding risks documented
- Owner review completed

## 9. Pilot extension

Any extension beyond the initial one-month period must be explicitly approved by the owner and documented.

An extension does not itself authorize production release or remove any production gate.

## 10. Required Stage 27 evidence

Stage 27 should not be marked implementation-complete until the controlled pilot produces a reviewable evidence package containing:

- Participant/scope record
- Test plan
- Test results
- Defect register
- Accessibility/device results
- Offline/low-bandwidth results
- Curriculum verification findings
- Security/privacy/safeguarding findings
- User feedback summary
- Risk register
- Pilot exit review
- Owner decision record

## 11. Release boundary

Stage 27 does not authorize production publication.

Pilot success, positive feedback or completion of testing does not override unresolved production security, privacy, safeguarding, hosting, authentication, database, payment, accessibility, curriculum or independent-review requirements.
